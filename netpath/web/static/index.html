    IP CONFLICTS

    A conflict means the same address has answered as two different MAC addresses — either directly on the wire across two scans, or the wire disagrees with what the DHCP server's own lease record says. Neither side clears itself; mark one resolved once you know what happened.

    DHCP SERVER

    Read-only: scopes and leases only, never a write. Authenticates as whichever Windows account runs SappiWhere, or a matching Windows Credential Manager entry for that server's name — nothing is stored here.

    Select an event to see its detail — the exact command that ran and the raw output it returned.

    These apply across every module. NetPath's worker pool, retention and destination defaults are under Settings on the NetPath tab; the collector's listener, sampling and storage are under Settings on the NetFlow tab.

    REVERSE DNS

    Shared by both modules: NetPath names hop addresses with it, NetFlow names flow endpoints. Each address is queried once per cache period, so a quiet Debug log means everything is already known.

    Three attempts per address: the system resolver, then a PTR query straight to the server named above if one is given, then nslookup. The fallbacks matter for internal addresses whose reverse zone the system resolver will not answer for — if nslookup finds a name, so will this. The Debug log records which method answered.

    ASN / OWNER LOOKUP

    Shown beside the hostname in NetPath's route graph, so you can see which network a route is on and where it leaves your own provider. Uses Team Cymru's DNS-based whois, which needs a resolver that can reach the public internet — this may need to be a different server than the one configured for reverse DNS above if that one only answers for internal addresses. Private, loopback and carrier-grade-NAT addresses are never looked up: no query is ever sent for them.

    REFRESH RATES

    Set per module because they want different rates. The route graph is cheap and benefits from feeling live; the flow charts are aggregations over a whole window and barely change in a few seconds, so a slow rate costs nothing and saves a lot of work. The Debug page's elapsed counters advance smoothly ten times a second without asking the server again, so its rate only controls how often new events and worker state are fetched.

    DATA FILES

    Checked every 15 minutes. When a file is over its cap the oldest records are deleted until it fits, so the cap wins over the retention setting. For IPAM that means the oldest scan history first — subnets, discovered hosts and open conflicts describe the network as it is now, not a log, so they aren't what a size cap trims.

    The application file holds settings, accounts and the shared reverse-DNS cache. It has no cap because it does not grow with traffic — it is the one to back up, and the other four files can all be rebuilt by simply collecting again.

    SIGN-IN

    Idle timeout signs a session out after this long with no mouse or keyboard activity in the browser — a tab left open in the background does not by itself count as activity. Maximum session length is a hard ceiling: signed out this long after signing in regardless of activity. Changing either applies to every session at the next check, not only new ones.

    YOUR PASSWORD

    At least 12 characters. A short phrase is easier to remember and harder to guess than a mangled word. Changing it signs out every session using this account, including this one.

    USERS

    Every account has full access; there are no roles yet, so adding one is an administrative act. A new user must change the initial password when they first sign in.
