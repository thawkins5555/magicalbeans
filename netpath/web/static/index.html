      REVERSE DNS
      
      
      
      
      
      
      
    Shared by both modules: NetPath names hop addresses with it, NetFlow names
        flow endpoints. Each address is queried once per cache period, so a quiet Debug log
        means everything is already known.
    
      
    Three attempts per address: the system resolver, then a PTR query straight
        to the server named above if one is given, then nslookup. The fallbacks matter for
        internal addresses whose reverse zone the system resolver will not answer for — if
        nslookup finds a name, so will this. The Debug log records which method answered.
    
    
    
    
    
      ASN / OWNER LOOKUP
      
      
      
      
    Shown beside the hostname in NetPath's route graph, so you can see which
        network a route is on and where it leaves your own provider. Uses Team Cymru's
        DNS-based whois, which needs a resolver that can reach the public internet — this may
        need to be a different server than the one configured for reverse DNS above if that one
        only answers for internal addresses. Private, loopback and carrier-grade-NAT addresses
        are never looked up: no query is ever sent for them.
    
    
    
    
    
      REFRESH RATES

      DATA FILES
      
      
      
      
      
      
      
      
      
      
      
      
      
      
      
      
      
      
      
    
      
    Checked every 15 minutes. When a file is over its cap the oldest records are
        deleted until it fits, so the cap wins over the retention setting. For IPAM that means the
        oldest scan history first — subnets, discovered hosts and open conflicts describe the
        network as it is now, not a log, so they aren't what a size cap trims.
    
      
    Nodes is three files: the device inventory and its event log, the metric
        history (samples and hourly rollups — the one that grows), and the uploaded MIBs. The
        MIB file has no cap: a MIB is not history, and trimming it would stop traps decoding.
        The metric history cap takes the raw samples first and then, once those are at their
        floor, the oldest hourly rollups — so a cap set low enough shortens how far back a wide
        chart can go, whatever the rollup retention setting says.
    
      
    The application file has no cap because it is the one file worth
        backing up.
    
    
    
    
    

    
    
    
    
      SIGN-IN
      
      
      
    Idle timeout signs a session out after this long with no mouse or keyboard
        activity in the browser — a tab left open in the background does not by itself count as
        activity. Maximum session length is a hard ceiling: signed out this long after signing in
        regardless of activity. Changing either applies to every session at the next check, not
        only new ones.
    
    
    

    
    
      DEVICE WEB TUNNELS
      
      
    The WEB button on a Nodes device opens a short-lived tunnel from this
        machine to that device's own web interface, on a port from this range. Write it as
        low-high, or 0 to let the operating system pick any free port.
        The range needs an inbound TCP rule in this host's firewall for browsers on other
        machines to reach it — on Windows the first bind of an unopened port raises the usual
        allow/deny prompt, which is why a named range beats an ephemeral one. A tunnel admits
        only the address the operator's browser connected from, closes after 15 minutes with no
        traffic, and needs the account's web permission.
    
    
    

    
    
      DIRECTORY (LDAP)
      
    Lets accounts created below with "Sign in via LDAP directory" verify their
        password against a directory server instead of a locally stored one. Local accounts are
        unaffected either way, and stay available as a fallback — which is also why the last
        local administrator can never be removed while only directory administrators remain (see
        the USERS section below).
    
      
      
      
      
    {username} is replaced with the account's username, which may
        only contain letters, digits, dot, dash and underscore — the same rule every username in
        this application already follows — so nothing typed at sign-in can change which entry the
        bind targets.
    
      
      
    Off by default. A simple bind sends the password inside the request itself
        — without TLS (an ldaps:// URL) that is in the clear on the wire, and this
        client refuses to do it until this is switched on. Prefer ldaps:// instead of
        turning this on wherever the directory supports it.
    
      
      
    
        
      
    
      
    
      
    
        
        
        
      
    
      
    Tests a bind against the settings above (or the saved
        ones, for any left blank) without saving anything or creating a session.
    
    
    
    
    

    
    
    
    
      USERS
      
    Your own password is changed from the Account button in the top
        bar, reachable regardless of what you have access to here — everything below needs
        write access to Settings.
    
      
    
      
    
        
        
        
        
        
        
      
    
      
      
    
        
        
      
    
      
    
      
    
      
    A new user must change the initial password when they
        first sign in, and starts with whatever access is set above — write implies read, and
        nothing checked means no access to that module at all. An LDAP account has no local
        password at all — the initial-password field above is ignored for one — and its password
        is only ever changed in the directory.
    
      
    
    
    
    
    

    
    
    
    
      API TOKENS
      
    A token authenticates automation the same way a signed-in session
        authenticates a browser, with the account's own permission grants and no idle timeout —
        so an unattended script does not have to hold a person's password against the sign-in
        timeout above. Send it as Authorization: Bearer <token>. The token
        itself is shown once, right after you create it, and never again.
